# Contributing to json5

This guide covers how the project is laid out and how to test and build the
package. All commands are meant to be run from the project root (the folder
that contains `DESCRIPTION`), unless noted otherwise.

## Requirements

- R >= 4.0.0
- Runtime dependency: `jsonlite`
- Development: `testthat` (>= 3.0.0), `knitr`, `rmarkdown`, `roxygen2`,
  `pkgload`
- System tools: `pandoc` (vignette), a TeX distribution with `pdflatex` (PDF
  manual), and `tidy` (HTML manual check)
  
Install the required software on ArchLinux with:

```sh
sudo pacman -S textlive tidy pandoc-cli
```

Install the R packages with:

```sh
Rscript -e 'pak::pak(c("jsonlite",
                       "testthat",
                       "knitr",
                       "rmarkdown",
                       "roxygen2",
                       "pkgload"))'
```


## File structure

This is the structure of the project:

```
json5/
├── DESCRIPTION            package metadata and dependencies
├── NAMESPACE              exports (generated by roxygen2, do not edit)
├── NEWS.md                changelog
├── README.md              overview and usage
├── LICENSE, LICENSE.md    MIT license (CRAN stub and full text)
├── contribution.md        this file (excluded from the build)
├── .Rbuildignore          files left out of the package tarball
├── R/
│   ├── json5-package.R    package-level documentation
│   ├── tokenize.R         lexer: one regex splits the input into tokens;
│   │                      error helpers with line/column positions
│   ├── read.R             parse_json5(), read_json5(), json5_to_json(),
│   │                      validate_json5(): JSON5 -> JSON transcoding,
│   │                      structure checks, and attaching comments
│   └── write.R            to_json5(), write_json5(): R -> JSON5, including
│                          comments, quoting, and trailing commas
├── man/                   Rd help files (generated by roxygen2, do not edit)
├── vignettes/
│   └── json5.Rmd          reading, parsing and writing walkthrough
├── inst/
│   ├── COPYRIGHTS         third-party material and its licenses
│   └── extdata/
│       └── example.json5  json5.org example used by the vignette
└── tests/
    ├── testthat.R         test runner used by R CMD check
    └── testthat/
        ├── test-read.R         parsing and error messages
        ├── test-write.R        writer options and output
        ├── test-comments.R     comment preservation and round trips
        ├── test-conformance.R  runs the official conformance suite
        └── json5-tests/        official json5-tests suite (vendored
                                unmodified; do not edit)
```

How the parser works, in short:

1. `tokenize()` (`R/tokenize.R`) splits the text into typed tokens.
2. `json5_transcode()` (`R/read.R`) validates the token stream against the
   JSON5 grammar, rewrites it as strict JSON, and records comments with their
   paths.
3. `jsonlite::parse_json()` turns the JSON into R objects.
4. The comments are attached to the R objects as `comment()` attributes.

The writer does the reverse: `jsonlite::toJSON()` produces JSON, and
`R/write.R` re-emits it in JSON5 style with the comments.


## Documentation

Help files and `NAMESPACE` are generated from the `#'` roxygen comments in
`R/`. After changing them, regenerate:

```sh
Rscript -e 'roxygen2::roxygenise()'
```

Commit the regenerated `man/` and `NAMESPACE` files together with the code
change.


## Testing

Run the whole test suite against the source tree (no install needed):

```sh
Rscript -e 'testthat::test_local()'
```

Run a single test file:

```sh
Rscript -e 'pkgload::load_all(); testthat::test_file("tests/testthat/test-write.R")'
```

Or only the tests whose file name matches a pattern:

```sh
Rscript -e 'testthat::test_local(filter = "comments")'
```

`test-conformance.R` checks every file in `tests/testthat/json5-tests/`. Do
not edit that folder. If the reference suite disagrees with this package on
an error position, add the case to `position_skips` in `test-conformance.R`
with a comment explaining why.

For quick experiments, load the package from source in an interactive R
session:

```r
pkgload::load_all()
parse_json5("{a: 1, // note\n b: [1, 2,],}")
```


## Building

Build the source tarball outside the project folder, so that build output does
not end up in the source tree:

```sh
cd ..
R CMD build json5
```

This installs the package temporarily, builds the vignette, and writes
`json5_<version>.tar.gz` to the current directory.

Install the built package:

```sh
R CMD INSTALL json5_0.1.0.tar.gz
```


## Checking before creating PullRequest

Run the CRAN checks on the built tarball:

```sh
R CMD check --as-cran json5_0.1.0.tar.gz
```

The goal is `Status: OK`.

Before a release, make sure to:

- Bump `Version` in `DESCRIPTION` and add an entry to `NEWS.md`
- Regenerate the documentation (see above)
- If you add third-party material, list it in `inst/COPYRIGHTS`
- If you add files at the project root that are not part of the package,
  add them to `.Rbuildignore`.
